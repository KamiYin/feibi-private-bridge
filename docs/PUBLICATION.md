# 公开发布说明

## 内容范围

本仓库由本地已审查项目中明确选定的源码、测试、协议参考和许可文本构建。没有从运行目录整体打包，也没有复制旧 Git 历史。

不包含真实 API 密钥、微信令牌、DPAPI 文件、隧道标识、本人绑定值、完整回调、主机标识、用户邮箱、真实请求 ID、私人聊天、医疗资料、浏览器状态、日志、原始运行清单或已登录环境。通用官方来源、协议路径、回环默认端口、算法和合成测试数据保留，便于审查与复现。

`windows-pilot/BUILD_PROVENANCE.json` 和 `binary-build-info.txt` 只是原构建来源记录：其中构建版本、公开依赖和二进制哈希不代表公开包附有该二进制。原字段 `windows_execution_tested:false` 保留历史含义；后来的本人文字验收以专门文档为准。

## 与源目录的差异

1. 两处机器专属目录改为仓库根目录，保留私有 ACL、NTFS、祖先目录和有限清理检查；对应测试使用合成路径。
2. 测试中的试用日期换为合成日期，不携带原运行截止。
3. 原来依赖随包 EXE 的预检测试改为公开源码包的缺失二进制预期；哈希不匹配测试使用替身文件状态。
4. 三条历史测试明确定位实际 Run 分支，避免误命中新增的凭据导入分支。
5. 未复制原始说明和累计清单中的私人部署细节，改写为本组中文文档。保留必要来源与许可；二维码目录的 package.json 仅指定 CommonJS，不带依赖安装脚本或第三方维护者联系邮箱。
6. 保留源目录最新的成功轮询延迟优化，但明确标注它未进入本阶段的真人验收运行版本。

这些变化只发生在公开副本。整理不操作真实微信会话、运行进程、凭据或源目录。

## 发布前检查

待发布文本和路径按文件清单逐一检查；只允许文本源码、测试、文档、来源与许可。检查硬编码密钥、部署标识、个人路径、邮箱、真实回调、账号和二进制内容；合成 fixture 与公开第三方版权分别识别，不能只靠关键词删除。

提交采用新历史，作者使用与真实邮箱无关的占位身份。发布者还须确认 GitHub 最终提交元数据不自动注入私人邮箱。公开包准备完成不等于已推送，线上发布以实际仓库内容为准。

## 后续更新约定

阶段取得实质进展后再集中更新：追加时间线、说明代码版本和验证证据、同步当前能力表，保留过去阶段的事实。不要把排错过程中的每个命令或聊天逐条上传。
