# 问题、根因与修复

## 协议与消息处理

| 现象 | 查明原因或证据 | 处理 |
| --- | --- | --- |
| 初次请求二维码 HTTP 405 | 较新协议使用 POST，官方 2.1.10 参考使用相同来源和路径的 GET；响应的实际产生方未定位 | 仅初次无凭据 POST 确定 405 后，允许一次同来源、同路径、无正文 GET；共用原时间预算 |
| 已拉取的本人文字被形态检查拒绝 | 旧解析对文本项附加字段、多个文本项、项级 ID 和可选字段要求过严 | 容纳这些文字形态，同时保留身份、私聊和文本类型检查 |
| 缺少回复上下文 | 入站文字本身可读，但无法可靠发送回复 | 保留文字，回复返回 `reply_context_unavailable`，不猜测上下文或收件人 |
| 空轮询被认作错误 | 空结果可能省略 `msgs`；缺失或空游标不表示可丢弃旧游标 | 接受空轮询，并沿用旧游标 |
| 成功发送被误判失败 | HTTP 成功且没有业务错误的回执可能省略 `ret` | 按该协议约定判 accepted；网络不确定仍为 unknown |
| 过期消息占满容量 | 旧容量判断把已经过期的正文也算入有效条数 | 过期请求不再占 100 条有效正文容量 |

## 启动、退出与诊断

| 现象 | 查明原因或证据 | 处理 |
| --- | --- | --- |
| 工具终端断开后桥接消失 | 复现了所属 Job 的所有者退出清理子进程机制；原断连事件由谁触发仍未知 | 独立 PS5.1 控制台承载、明确截止、同用户单实例；不宣称解决所有崩溃恢复 |
| 显示“窗口已启动”但不能证明后端在线 | 创建宿主和后端握手是不同阶段 | 后端产生 `bounded_windows_started` 才记 started；窄字段结果文件保存固定阶段和错误码 |
| 本机窗口工具找不到独立控制台 | UI 可达性不足以控制后台状态 | 既有私有目录中交换有限控制命令，复用原授权和截止；不新增公网控制入口 |
| 分不清收信失败、空结果或过滤 | 只看事件数量无法定位管道哪一段未完成 | 记录内存计数、固定形态原因、HTTP 状态与时间；不记录消息正文、用户身份、游标或 token |
| PowerShell 7 父环境下安全模块解析异常 | 当前 Windows PowerShell 可能继承不兼容模块查找路径 | 显式导入当前 PS5.1 自带安全模块，保留原环境 |
| 凭据输入 / 管道卡住 | 交互宿主、重定向和阻塞写入存在生命周期差异 | 专用 PS5.1 STA File 宿主、单次隐藏输入、有限握手与异步写入，失败进入既有清理 |

## 运行连续性

- **累计 I/O 触发停机**：累计日志量或累计控制输入会随正常运行增长，不能代表当前单条输入或队列超限。修复删除累计停机条件；日志直接排空不保存，单条输入和待处理队列限制继续生效。
- **回调暂时失败五次后放弃**：累计尝试次数不足以判断事件不可再投递。修复保留原退避，终止由成功、明确拒绝、订阅失效、消息过期或本轮截止决定。
- **长收信轮询与回调相互阻塞**：一个调度路径等待另一个长网络请求完成，延后收信或通知。修复各自单独保持进行中标记，收信仍只有一个 poller。
- **额外一秒等待**：成功拉取后还设下一次轮询时间，增加本地等待。源码已去掉该等待，失败退避保留；此优化尚未进入本次手机验收实例。
- **平台唤醒延迟**：本地材料包含少量“本地到平台”与“平台到会话唤醒”的耗时样本，提示延迟不全在本地。样本不足以给出稳定性统计或平台根因，也没有擅自改平台队列。

## 排错顺序

先看预检与实际启动回执，再看会话是否完成本人绑定，最后按“拉取 → 接纳 / 过滤 → 排队 → 回调 → 原会话读取 → 回复 API → 手机确认”定位。API accepted 证明接口受理；手机实收需要用户确认。

401 / 403、明确的授权或会话失效、未审核来源、验证码流程等继续按现有停止或人工处理分支处理。发送结果 unknown 不自动重发，以免给本人重复发送。
